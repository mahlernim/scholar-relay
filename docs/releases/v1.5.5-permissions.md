# ScholarRelay v1.5.5 permission justification

This release adds the required host permission `https://accounts.google.com/*` for the existing bounded Notebook login check. Chrome can otherwise hide the final sign-in response behind a cross-origin fetch error. The check follows redirects with the browser-managed session and uses the final response URL and HTTP status to distinguish a recognized sign-in destination from an access restriction or an unrecognized response.

Normal Notebook discovery reads can follow redirects to this same sign-in host. The optional probe starts at `/login` on an existing Notebook app host only after normal Notebook pages fail to provide usable session information. The probe shares the existing discovery deadline and concurrent callers share one request. Neither path reads the Google Accounts page body, submits a password or verification code, selects an account, or retries a content mutation. A timeout, blocked response, or intermediate redirect alone does not establish sign-out. Rate-limit and other conflicting response evidence keep their existing precedence.

No `webRequest` or Cookies API permission is added. No script is injected into Google Accounts pages. Optional website grants and existing Notebook host grants are unchanged. Full redirect URLs, query parameters, and page bodies are not stored. Only the connection error category and safe diagnostics can be retained with a queued job for recovery. The developer receives no account or browsing data.

## Chrome Web Store host permission justification

Access to https://accounts.google.com/* is needed only for a bounded, read-only Notebook login check to follow the user's existing browser session and inspect the final response URL and HTTP status. This distinguishes a recognized sign-in response from access restrictions when Chrome would otherwise hide the result. The extension does not read the sign-in page body, passwords, verification codes, or cookies through an API, inject scripts into Accounts pages, or monitor browsing. It stores no full redirect URLs or query parameters. A timeout or intermediate redirect alone is never treated as sign-out.
